# База данных

Одна база SQLite (`DATA_PATH`, по умолчанию `data/site.sqlite`) в режиме WAL. Схема создаётся и дополняется при запуске сервера (`server/store.js`, `store-extras.js`, `store-billing.js`): новые столбцы добавляются `ALTER TABLE`, данные не пересоздаются. Деньги хранятся целыми числами в минимальных единицах (копейки, центы), время — миллисекунды Unix.

## Таблицы

| Таблица | Что хранит | Сколько живёт |
| --- | --- | --- |
| `users` | почта, хэш пароля (scrypt), подтверждение почты, имя для обращения, тариф и его окончание, согласие на хранение чата, сохранённый способ автоплатежа (`autorenew_method_id`, провайдер и валюта) | пока есть аккаунт |
| `sessions` | хэш токена сессии и срок | 30 дней, удаляются при выходе |
| `auth_challenges` | коды подтверждения почты и сброса пароля (только хэши), попытки | 10 минут |
| `birth_profiles` | данные рождения владельца: дата, время, место, координаты, часовой пояс, момент UTC | пока есть аккаунт |
| `chart_profiles` | близкие на партнёрском и семейном тарифах: связь, имя, те же поля рождения | пока есть аккаунт; при удалении профиля удаляется и его переписка |
| `chat_messages` | переписка в чате, **только при согласии** | 180 дней и не больше 500 сообщений; отзыв согласия удаляет всё |
| `daily_quotas` | счётчики сообщений и писем за день | обновляются ежедневно |
| `orders` | заказы: тариф, срок, сумма и валюта, статус (`pending`, `paid`, `canceled`, `failed`, `refunded`), провайдер, номер платежа у провайдера, числовой номер счёта `invoice_no` (для Robokassa), автопродление | не удаляются: это учётные записи о платежах |
| `payment_events` | какие уведомления провайдера уже обработаны (защита от повтора) | можно чистить старше года |
| `metrics_daily` | обезличенные счётчики: просмотры, сообщения, ошибки, время ответа | бессрочно, персональных данных нет |
| `visitors_daily` | хэш посетителя за текущий день для подсчёта уникальных | удаляется на следующий день |

Пароли, коды и токены сессий в базе только в виде хэшей. Дата и место рождения и почта никогда не передаются модели: в чат уходит только рассчитанная карта.

## Персональные данные и 152-ФЗ

- База и резервные копии — на сервере в России: данные граждан РФ должны записываться и храниться в российской базе.
- Персональные данные: почта, имя, данные рождения (свои и близких), переписка. Для переписки отдельное согласие (`chat_history_consent_at`); для данных близких пользователь подтверждает, что вправе их передать (текст — в оферте и политике).
- Удаление аккаунта: стирать `birth_profiles`, `chart_profiles`, `chat_messages`, `sessions`, обезличивать `users` (почта → случайная, имя и хэш пароля — пусто). Заказы оставлять: `orders.user_id` стоит с `ON DELETE RESTRICT`, потому что платёжные записи нужны для бухгалтерии и чеков. Сейчас удаления аккаунта в API нет — это следующая задача.

## Резервные копии

`node scripts/db.js backup <путь>` делает согласованную копию работающей базы (`VACUUM INTO`). Рекомендуется раз в сутки по cron и хранить 14 дневных и 8 недельных копий в отдельном хранилище S3 у того же российского провайдера, с шифрованием. Раз в месяц проверять восстановление на тестовой машине.

## Когда переходить на PostgreSQL

SQLite хватает, пока сайт работает на одном сервере: тысячи пользователей и десятки сообщений в секунду для неё не нагрузка. Переходить стоит, если понадобится второй сервер приложения, отдельные отчёты по базе для команды или реплика для отказоустойчивости. Тогда — управляемый PostgreSQL у того же провайдера (Timeweb Cloud, Selectel или Yandex Cloud, регион Россия). Код хранилища собран в трёх модулях `server/store*.js`, поэтому замена затрагивает только их.
