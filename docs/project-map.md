# Карта проекта простым языком

Этот документ помогает найти нужную папку или файл в проекте «МояФортуна». Его можно передать новому участнику команды, чтобы объяснить, как устроен сайт.

Структура сверена с локальным кодом 11 ноября 2026 года. Работающий сервер в рамках этой проверки не проверялся. Обзор сервисов, ссылки на сайт, Figma и кабинеты — в [путеводителе по проекту](project-guide.md).

## С чего начать

Основная папка на этом компьютере — `E:\ai сайт`. Внутри неё:

- `prototype/` — то, что видит посетитель: экраны, кнопки, оформление.
- `server/` — то, что происходит после нажатия кнопки: вход, расчёт, ответ, проверка подписки.
- `config/` — настройки: цены, ограничения, тексты и правила.
- `docs/` — объяснения, инструкции и отчёты.

Например, цвет кнопки меняют в интерфейсе, число доступных вопросов — в настройках, а порядок проверки оплаты — на сервере.

## Общая схема

1. Человек открывает сайт или мини-приложение в Telegram.
2. Интерфейс отправляет запрос серверу: например, «сохрани данные рождения».
3. Сервер проверяет вход и права доступа, читает данные из базы или выполняет расчёт.
4. Если нужен текстовый ответ Фортуны, сервер обращается к Ollama — программе для запуска обученного помощника.
5. Результат возвращается на экран.

Письма и платежи подключены отдельными частями. Сам факт открытия страницы после оплаты не выдаёт доступ: сервер проверяет уведомление от платёжного сервиса.

## Где находятся экраны

Основной HTML-файл интерфейса — `prototype/miniapp/index.html`. Разделы приложения используют общую оболочку: адрес страницы не обязательно соответствует отдельному HTML-файлу.

| Что нужно найти | Где начать |
| --- | --- |
| Общая работа интерфейса | `prototype/miniapp/miniapp.js` |
| Общие стили | `prototype/miniapp/miniapp.css`, `miniapp-desktop.css` в той же папке |
| Главная страница | `prototype/miniapp/fortuna-home.css`; поведение — в коде приложения |
| Личный кабинет | `prototype/miniapp/screens-account.js` |
| Чат | `prototype/miniapp/screens-chat.js` |
| Карта дня | `prototype/miniapp/screens-card.js`, `card-day.css`, `daily-card-choice.js` |
| Прогнозы | `prototype/miniapp/forecasts.css`; серверный расчёт — отдельно в `server/` |
| Подписка на телефоне | `prototype/miniapp/subscription-mobile.css`; связанные экраны — в коде приложения |
| Обмен данными с сервером | `prototype/miniapp/api.js` |
| Работа внутри Telegram | `prototype/miniapp/telegram-app.js` |
| Установка сайта на главный экран | `prototype/pwa.js`, `prototype/sw.js`, `prototype/manifest.webmanifest` |

Файл `.html` задаёт основу страницы, `.css` — внешний вид, `.js` — действия. Один экран может использовать несколько файлов.

По правилам проекта изменения интерфейса ведутся отдельным направлением. Задачи для него записываются в [docs/codex-ui-tasks.md](codex-ui-tasks.md).

| Профиль и близкие люди | `server/routes/profiles.js`, `server/birth-input.js`, `server/birth-time.js` |

| Применить методику Анны | `server/anna-method.js` |
| Прогноз на день и неделю | `server/daily-forecast.js`, `server/personal-forecast.js`, `server/weekly-forecast.js` |
| Принять вопрос в чате | `server/routes/chat.js` |
| Подготовить запрос Фортуне и получить ответ | `server/local-chat.js`, `server/ollama.js` |
| Проверить содержание ответа | `server/chat-safety.js`, `server/astro-fact-guard.js`, `server/chart-answer-check.js` и связанные проверки |

Расчёты и текстовые пояснения разделены. Положения планет вычисляет код, а обученный помощник формулирует ответ с переданными ему данными.

## Где хранятся данные и доступы

На сервере аккаунты, данные рождения, подписки и другие записи хранятся в PostgreSQL. Для локальной разработки без `DATABASE_URL` приложение создаёт PGlite в `data/pglite`. Это локальная база, которая позволяет работать без установки отдельного сервера PostgreSQL.

- `server/db.js` — подключение к базе.
- `server/schema.js` — описание таблиц и изменений их структуры. Новые изменения добавляют в конец.
- `server/store.js`, `server/store-extras.js`, `server/store-billing.js`, `server/store-welcome.js` — сохранение и чтение записей.

Рабочие ключи и пароли хранятся отдельно от кода. Пример службы в `deploy/anna-site.service` читает их из `/etc/anna/site.env`. Это путь на сервере Linux, а не на Windows. Файл `deploy/env.example` показывает названия настроек, но не содержит рабочих доступов.

Материалы обучения, записи и веса помощника по правилам проекта находятся отдельно — в `D:\AnnaAI`. Их не нужно переносить в GitHub. Программы для работы с ними находятся в `training/`; инструкция — в [training/README.md](../training/README.md).

Файлы на компьютере, коммит в GitHub и опубликованная версия сайта — разные вещи. Сохранение файла или отправка коммита сами по себе не обновляют сервер. Фактическую папку запуска и выбранную версию Фортуны проверяют на сервере перед публикацией.

## Как запустить сайт на компьютере

Нужен Node.js версии 24.15 или новее. В PowerShell:

```powershell
Set-Location 'E:\ai сайт'
$env:TEMP = 'E:\ai-site-intl-tmp'
$env:TMP = 'E:\ai-site-intl-tmp'
$env:TMPDIR = 'E:\ai-site-intl-tmp'
$env:npm_config_cache = 'D:\AnnaAI\tmp\npm'
New-Item -ItemType Directory -Force $env:TEMP, $env:npm_config_cache | Out-Null
npm ci
npm start
```

Настройки временных файлов нужны, чтобы не заполнять диск C:. `npm ci` устанавливает библиотеки по зафиксированному списку; при обычном запуске уже установленного проекта достаточно `npm start`.

Открыть в браузере: [http://127.0.0.1:3000](http://127.0.0.1:3000). Остановить сервер — `Ctrl+C` в том же окне. Для проверки состояния есть [http://127.0.0.1:3000/api/health](http://127.0.0.1:3000/api/health).

Без дополнительных настроек внешний почтовый сервис, оплата и текстовые ответы через Ollama не включаются автоматически. Локальный запуск страницы не означает, что эти подключения готовы.

## Как проверять изменения

В отдельном окне PowerShell, из корня проекта:

```powershell
node --test ./test/*.test.js
```

Эта команда проверяет основное приложение. Команда `npm test` запускает общий поиск тестов и в этой рабочей папке может захватить вложенные копии материалов обучения. При ошибке важно проверить, к какой папке относится упавший тест.

Для резервных копий предусмотрен `scripts/db.js`, для ежедневного обслуживания — `scripts/daily.js`, для статистики — `scripts/stats.js`. Перед запуском таких команд нужно прочитать соответствующую инструкцию: они работают с выбранной базой и могут менять данные.
