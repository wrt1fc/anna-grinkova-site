# Чат «Сервер сайта и оплата»

**Модель:** Sonnet 5.5. **Рабочая папка:** `E:\ai-site-intl`.

## Как начать

> Прочитай `docs/sessions/03-backend-payments.md`. Задача: `<что нужно>`.

## Что есть

- API: регистрация с кодом из письма, вход, сброс пароля, кабинет, данные рождения, близкие (`/api/profiles`), чат (SSE, `/api/chat`), история чата с согласием, выгрузка и удаление аккаунта (`/api/me/export`, `DELETE /api/me`), тарифы и оплата (`/api/billing/*`).
- Оплата: `server/billing/service.js` (заказы, продление, сверка зависших заказов, возвраты), `yookassa.js` (РФ, рубли; вебхук по IP и перечитывание платежа), `robokassa.js` (иностранные карты, USD/EUR; подписи паролями 1 и 2). Ежедневно `scripts/daily.js`: очистка, сверка, автопродления.
- Письма: `server/mail.js` — Unisender Go для российских ящиков, Brevo для зарубежных.
- Защита: лимиты по IP и по адресу письма, блокировка входа по паре «почта + IP», дневной лимит неверных кодов, ограничение чата по IP и аккаунту, не больше 5 неоплаченных заказов в час.
- Документация: `docs/payments.md`, `docs/database.md`, `docs/codex-ui-tasks.md` (API для интерфейса).

## Что впереди

- ЮKassa и Robokassa — после юрлица, оферты и политики на сайте; сначала тестовые платежи (`ROBOKASSA_TEST=1`, только не в production).
- Возвраты Robokassa приходят без уведомления — закрывать вручную (`scripts/set-plan.js`).
- Капча на регистрации (Yandex SmartCaptcha) — нужен ключ.
- Нагрузочный тест чата на боевом сервере (`CHAT_MAX_CONCURRENT`, `OLLAMA_NUM_PARALLEL`).
- При изменении API — обновлять `docs/codex-ui-tasks.md` для Codex.

## Правила

- Сначала тест (`test/*.test.js`), потом код; в конце `npm test`, все должны проходить.
- Хранилище асинхронное; изменения тарифа, профилей и оплаты — в `store.inTransaction(async (tx) => …)` с `tx.lockUser(userId)`, внутри только `tx.*`.
- Новые таблицы и столбцы — только новой миграцией в конец `server/schema.js`.
- После изменений в оплате и авторизации — чат «Проверка уязвимостей».
