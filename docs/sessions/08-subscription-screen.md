# Подписка и оплата — макеты Figma

Создано 25.10.2026 по запросу пользователя: отдельный экран оплаты сначала в Figma, во всех размерах «Адаптива».

## Что есть на сайте

Экран перенесён на `/podpiska`, переход находится в кабинете в блоке «Подписка и оплата». `/api/billing/subscription-links` возвращает ссылки с почтой текущего пользователя, `/api/billing/subscription` — состояние подписки. Секретный ключ остаётся на сервере; браузер получает только готовые платёжные ссылки.

В кабинете уточнены подписи: «Выйти из аккаунта» и «Указать город вручную».

## Содержание и поведение

- Одна подписка, два срока: 990 ₽ / 30 дней и 2070 ₽ / 90 дней. Для второго срока — 690 ₽ за каждые 30 дней, экономия 900 ₽ по сравнению с тремя отдельными оплатами по 990 ₽.
- Возможности взяты из `config/plans.json`: 60 сообщений помощнику и 5 разборов с метафорической картой в день, один пользователь. Бесплатный доступ — 5 сообщений в день.
- В обеих карточках одинаковые возможности; различаются срок и стоимость.
- Блок с почтой показывает аккаунт, на который оформляется подписка. `anna@example.com` — только пример в макете. На сайте использовать почту вошедшего пользователя.
- Кнопки Figma открывают предоставленные пользователем ссылки Prodamus. При реализации на сайте получать ссылки через API с подстановкой почты, не заменять их статическими URL из макета.
- Тестовую оплату 1 ₽ в публичных макетах не показывать.
- Оплату подтверждает подписанное уведомление Prodamus. Возврат из платёжной формы сам по себе не подтверждает оплату.
- После входа с экрана подписки пользователь остаётся на нём. Для гостя платёжная кнопка сначала открывает вход.
- По возвращении на вкладку состояние обновляется; доступна кнопка «Проверить подписку и оплату». Она также добавлена в макеты Figma.
- При выходе из аккаунта платёжные ссылки и почта очищаются; запоздавший ответ API не может вернуть их. При ошибке оплаты ссылки отключены до успешной повторной проверки.
- Не обещать автоматическое продление, конкретные способы оплаты или поддержку зарубежных карт без проверки настроек платёжной формы.

Карточки сроков, преимущества и переход из кабинета оформлены компонентами в UI-kit. Экраны состоят из редактируемых текстов, экземпляров компонентов и auto-layout; используются существующие шрифты, стили и переменные файла.

## Проверка

Для девяти адаптивных экранов проверены границы дочерних слоёв, шрифты и платёжные ссылки. Визуально проверены широкий экран и телефон; исправлена ширина мобильных кнопок. В изменённых мобильных профилях устранено наложение заголовка данных рождения на описание.

После переноса на сайт:

- `npm test`: 211 тестов, все прошли; дополнена проверка прямого адреса `/podpiska`, ресурсов, noindex и отсутствия персональных ссылок в публичном HTML.
- Браузер: 13 ширин (360–2560), переход из кабинета, вход с экрана подписки, ссылки на оба срока с почтой аккаунта, отсутствие тестового продукта, возврат по истории браузера.
- На временной локальной базе проверены активация по подписанному уведомлению, игнорирование `?payment=success`, выход из аккаунта, ошибка сервиса и повторная проверка, истёкшая подписка, запоздавший ответ после выхода.
- Остальные страницы: 84 проверки вёрстки (7 страниц × 12 ширин), без наложений и горизонтальной прокрутки; ошибок JavaScript не обнаружено.

Браузерные отчёты: `E:\ai-site-intl-tmp\subscription-qa\results.json` и `E:\ai-site-intl-tmp\layout-audit-subscription\results.json`. В контрольных прогонах реальную оплату не выполняли: открытие Prodamus проверялось с локальным перехватом запроса, уведомление подписывалось тестовым ключом только для временной локальной базы.
