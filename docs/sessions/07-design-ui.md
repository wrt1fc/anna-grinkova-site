# Чат «Дизайн и интерфейс»

**Модель:** Sonnet 5.5; Opus — для сложной вёрстки или если результат не устраивает. **Рабочая папка:** `E:\ai-site-codex` (ветка `feat/account-payments`).

Если интерфейс в этот момент делает Codex, этот чат не нужен — задачи для него лежат в `docs/codex-ui-tasks.md`. Не работать в одной папке одновременно с Codex.

## Как начать

> Прочитай `docs/sessions/07-design-ui.md`, `DESIGN.md` и нужный раздел `docs/codex-ui-tasks.md`. Задача: `<что сделать>`.

## Где что

- `prototype/index.html` — все разделы на одной странице: `data-page="home|day|week|chat|account"`.
- Стили: `styles.css` (основа), `polish.css` (доводка), `motion-layout.css`, `chat.css`, `tarot.css`, `birth-time.css`. Шрифты — `prototype/assets/fonts/`.
- Скрипты: `app.js` (переходы между разделами, вход, кабинет, карта дня), `chat.js`, `birth-ui.js`, `birth-time.js`.
- `DESIGN.md` — цвета, шрифты, композиция; `design/svg/` — макеты для Figma; `design/source/` — исходные фото Анны.
- `docs/codex-ui-tasks.md` — что нарисовать поверх готового API, разделы 1–10 (согласие и юр. страницы, тарифы и оплата, близкие, история чата, приложение на телефоне, адреса страниц).

## Что можно и нельзя

- Можно: всё в `prototype/` и `design/`, кроме исключений ниже.
- Нельзя: `server/`, `training/`, `config/`, `scripts/`, `test/` — это сервер и модель. Если для интерфейса нужен новый API, записать задачу в `docs/sessions/03-backend-payments.md` или сказать пользователю.
- Не удалять и не менять: `prototype/sw.js`, `prototype/pwa.js`, `manifest.webmanifest`, в `<head>` — manifest, иконки, og-теги с `__PUBLIC_URL__`, canonical, preload шрифта, `pwa.js`.
- Атрибуты `data-page="…"` у разделов не убирать: по ним сервер показывает нужный раздел для поисковиков.
- Ссылки между разделами — обычные адреса (`/karta-dnya`, `/chat`, `/kabinet`), не `#day`. Из скриптов — `window.navigateTo('account')`. Новая страница — адрес в `config/seo.json` (это делает чат «Тексты и SEO») и в `ROUTE_PATHS` в `app.js`.

## Правила оформления

- Палитра и шрифты — строго из `DESIGN.md`: тёмный тёплый фон, бронза и золото; Wix Madefor Display, Roboto, Playfair Display Italic.
- Только свои ресурсы: никаких внешних шрифтов, скриптов и картинок — CSP разрешает только свой домен.
- Без слов «ИИ», «нейросеть», «модель» в интерфейсе.
- Instagram — со звёздочкой и сноской про Meta в подвале.
- Институт — «Институт прогрессивной психологии».
- Один `<h1>` на раздел; картинкам со смыслом — осмысленный `alt`, декоративным — `alt=""`.
- Телефон: проверять на ширине 375 px; поля ввода — шрифт не меньше 16 px; цели касания не меньше 44×44; отступы `env(safe-area-inset-*)`.
- Доступность: фокус виден, контраст текста не ниже 4.5:1, всё работает с клавиатуры.
- После правок CSS или JS — увеличить номер `?v=` у подключения в `index.html`, иначе браузеры возьмут старую версию из кэша.

## Как проверять

1. В `E:\ai-site-codex`: `npm start` (на Windows перед этим `$env:TMPDIR='E:\ai-site-intl-tmp'`), открыть `http://127.0.0.1:3000`. База поднимется сама (PGlite), модель не нужна — чат ответит, что временно недоступен, если Ollama не запущена.
2. Посмотреть каждый изменённый раздел на широком экране и на 375 px, без ошибок в консоли браузера.
3. `npm test` — все тесты должны проходить (интерфейс их не должен ломать, но они проверяют `<head>`, адреса и service worker).
