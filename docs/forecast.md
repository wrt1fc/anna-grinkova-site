# Дневной прогноз: расчётная модель

## Что работает

`GET /api/forecast/day` выдаёт общий прогноз на текущую календарную дату в `Europe/Moscow`. В `server/daily-forecast.js` библиотека [Astronomy Engine](https://github.com/cosinekitty/astronomy) версии 2.1.19 (MIT) рассчитывает геоцентрические тропические долготы Солнца и Луны на 12:00 МСК. По долготам определяются знаки; угол Луны относительно Солнца даёт приближённую стадию лунного цикла. Результат содержит точную дату и исходные численные долготы, чтобы текст можно было проверить. Расчёт кэшируется в памяти сервера до смены дня.

Карта выбирается из 22 старших арканов по SHA-256 даты. Это воспроизводимый цифровой выбор, а не физическая вытяжка карты. Текст составляет локальный редакционный модуль из положения Луны, стадии лунного цикла и трактовки карты. Если задан `FORECAST_LOCAL_MODEL`, локальный Ollama может переформулировать только текст. Запрос ограничен 240 выходными токенами, выполняется один раз на дату и отправляется только на `127.0.0.1:11434`. Ответ принимается, если сохранены положения Солнца и Луны, стадия цикла и название карты; иначе остаётся редакционный вариант. Рекомендуемая доступная модель — [qwen3:4b](https://registry.ollama.com/library/qwen3/tags). Она не установлена в текущем окружении, поэтому реальное качество её текста ещё не проверено. Платная облачная LLM не вызывается. Тексты Анны добавляются после получения её материалов и редакционного согласования.

Предварительный профиль подачи по записи и публичным публикациям описан в [отдельном документе](forecast-voice.md). При запуске локальной модели он читается из `config/forecast-style.json`. Это настройка текста, а не обученная модель. Материалы Анны для полноценной редакционной настройки пока не получены.

Страница «Карта дня» получает результат из API и заменяет им прежний неподвижный текст. Прогноз общий. Он не использует данные рождения и не должен называться персональным.

## Границы точности и следующий шаг

- Положение показано на полдень по Москве; Луна может сменить знак в течение суток. Для прогноза по часам нужен отдельный расчёт переходов.
- Для натальной карты нужно однозначно определить город рождения, координаты и часовой пояс на **дату рождения**. Нынешнее поле свободного текста этого не гарантирует. Следующий этап: каталог мест с выбором города и историческим часовым поясом, затем натальные долготы и транзитные аспекты с тестами на эталонных картах.
- В неделе пока остаётся прежний редакционный текст; API недели отвечает `501`.
- Перед персональными трактовками нужны проверенные правила интерпретации и набор примеров Анны. LLM будет писать по структурированным численным фактам, а не вычислять планетные положения.

## Sotis

Первый запрос прогноза за дату обращается к внутреннему `get.php` публичного веб-приложения Sotis. Сервер передаёт только дату, время 12:00 и фиксированный город Москву; имя, почта и данные рождения пользователя не отправляются. Из ответа читаются долготы Солнца и Луны. Если каждая отличается от локального расчёта не более чем на 0,2°, API возвращает `astronomy.sotis.status = "matched"` и оба значения. Если сайт недоступен, ответ изменился или расчёты расходятся, локальный прогноз остаётся доступным, а статус становится `"unavailable"`. Запрос выполняется один раз на дату на процесс и кэшируется. `SOTIS_VERIFY=0` отключает его.

Это рабочая, но предварительная интеграция: `get.php` не документирован как API. В [базе знаний Sotis](https://sotis-online.ru/knowledge/) описана работа пользователя с картами, но не опубликованы гарантия формата, лимиты и условия серверного доступа. Для устойчивого коммерческого запуска нужны API/условия доступа от Sotis или согласованный экспорт. Поэтому Sotis сейчас служит проверкой численных фактов, а основной расчёт выполняется локально.

Первую сверку уже добавили в тест: на [примерной карте Sotis](https://sotis-online.ru/?chr=dt:20260928104154;sx:m;cid:2729045;name:New%20chart) для 28.09.2026 10:41:54 (+03:00) Солнце показано как 5°12′30″ Весов, Луна — 25°56′07″ Овна. Локальные долготы отличаются менее чем на 0,02°; это проверяет два тела в один момент времени, но не заменяет полноценный набор эталонных карт.
