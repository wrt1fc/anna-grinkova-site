# Проверка через нидерландский сервер

11 ноября 2026 по запросу пользователя на его VPS `144.31.92.162` создан временный reverse proxy к основному сайту.

Адрес: `https://fortuna-nl.144-31-92-162.sslip.io:9443/`.

Это временное тестовое имя sslip.io, не настроенный домен `.com`. Запрос проходит через Нидерланды на `https://xn--80axddamoif3i.xn--p1ai`; редирект браузера на основной домен не используется. Приложение и база не копировались. Сертификаты проверяются на обоих соединениях. На входе используется ALPN HTTP/1.1. На сервере уже заняты 443 (VPN) и 8443, поэтому выделен 9443/tcp.

Конфигурация: `deploy/fortuna-nl-test.caddy` → `/etc/caddy/conf.d/fortuna-nl-test.caddy`; в основной Caddyfile добавлен единственный import. Предыдущий файл сохранён как `/etc/caddy/Caddyfile.before-fortuna-nl-20261111`. Правило UFW: `allow 9443/tcp`, комментарий `fortuna-nl-test`. Доступные ранее сервисы и VPN не перенастраивались.

Для запросов с Origin самого тестового сайта заголовок переводится на origin основного сайта. Сторонние Origin не переписываются и получают 403 от существующей защиты. Это проверено на пустом запросе входа: собственный Origin проходит проверку происхождения, сторонний отвергается. Внешние платёжные адреса, канонические ссылки и Telegram Main App остаются прежними. Разные домены имеют разные cookie-сессии; тестовый узел не выполняет автоматическую авторизацию. Узел не кэширует ответы и не пишет отдельный access log. Для постоянной эксплуатации нужны собственный домен, отдельная проверка авторизации/оплаты и корректное определение IP посетителя (сейчас основной сервер видит IP нидерландского прокси).

Проверки: конфигурация Caddy валидна; публичный HTTPS 200; браузерные сценарии 360/390/1440/1920 px (неделя, день, выбор даты, клавиатура, повтор после ошибки); полный файл главного изображения 2340444 байта; независимые проверки из Buffalo (US) и Falkenstein (DE) — 200 с валидным TLS. Подтверждение от пользователя с проблемным VPN ещё требуется.

Отключение теста: убрать только строку `import /etc/caddy/conf.d/fortuna-nl-test.caddy` из основной конфигурации, выполнить `caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile`, затем `systemctl reload caddy` и `ufw delete allow 9443/tcp`. Полную резервную конфигурацию не восстанавливать поверх более поздних изменений других сервисов.
