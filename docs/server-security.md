# Защита сервера

Сервер `195.209.219.31` (Immers.cloud, Ubuntu 26.04), вход: `ssh -i ~/.ssh/anna_site_ed25519 ubuntu@195.209.219.31`.

## Сделано (21.10.2026)

- **Вход:** только по ключу и только пользователем `ubuntu` (`AllowUsers`). Root и пароли закрыты (`/etc/ssh/sshd_config.d/50-hardening.conf`, `51-anna.conf`). Не больше 3 попыток за соединение, 30 секунд на вход. Пересылка X11 и агента выключена.
- **Firewall (ufw):** входящие закрыты, кроме 22, 80 и 443.
- **fail2ban:** 5 неудачных входов за 10 минут дают бан на час. Тем, кто попадается снова, бан растёт, до недели (`/etc/fail2ban/jail.d/anna.conf`).
- **Ядро и сеть:** `/etc/sysctl.d/60-anna-hardening.conf`: сервер не принимает перенаправления и маршрутизацию от источника, подозрительные пакеты пишутся в журнал, адреса ядра скрыты, защита ссылок в /tmp.
- **Обновления:** система обновлена (ядро 7.0.0-38, драйвер NVIDIA 615.71.10) и перезагружена. Обновления безопасности ставятся сами каждый день (unattended-upgrades). Сам сервер при этом не перезагружается, поэтому после обновления ядра его нужно перезагрузить вручную в спокойное время. Драйвер NVIDIA приходит из репозитория провайдера и сам не обновляется.
- **Лишнее убрано:** telnet удалён, ModemManager и udisks2 выключены. AppArmor работает.
- Служба провайдера `mount-fstabd` при загрузке пишет ошибку, потому что нет `/etc/fstab.d`. Это не опасно: она нужна только для дополнительных дисков.

## Проверка после установки сайта (21.10.2026)

- Наружу открыты только 22, 80 и 443. PostgreSQL (5432), сайт (3000) и Ollama (11434) слушают только `127.0.0.1`, а firewall блокирует попытки подключиться к ним извне.
- PostgreSQL: вход только по паролю (scram-sha-256) с самого сервера. У роли `anna` нет прав суперпользователя, она владеет только базой `anna`.
- Сайт работает от пользователя `anna` и не может менять свой код (`/opt/anna-site` принадлежит `ubuntu`). `/etc/anna/site.env`: root, права 600.
- HTTPS: TLS 1.2 и 1.3, 1.0 и 1.1 отключены. Заголовки HSTS, CSP, X-Frame-Options, nosniff, Permissions-Policy на месте. Сертификат на все четыре имени обновляется сам (certbot.timer).
- Служебные файлы (`/.git`, `/.env`, `package.json`, исходники) не отдаются. Обход путей даёт 400, POST с чужого сайта — 403.
- Версия Nginx скрыта (`server_tokens off` в `/etc/nginx/nginx.conf`, копия — `nginx.conf.bak-2026-10-21`).
- JupyterLab из образа провайдера (`jupyterlab.service`) выключен, его порт закрыт firewall. Файлы с его токеном доступны только `ubuntu`. Включать его нельзя: Jupyter даёт полный доступ к серверу.
- `npm audit`: уязвимостей в зависимостях нет.

## Защита от DDoS и полная проверка доступа (22.10.2026)

- **Nginx:** страницы и файлы — не больше 30 запросов в секунду с одного адреса (запас — 300), API — 30 в минуту (запас — 20), не больше 60 одновременных соединений с адреса. Кто превышает, получает 429. Медленные и молчащие соединения закрываются через 10–20 секунд. До 4096 соединений на процесс Nginx (было 768). Настройки — в `/etc/nginx/conf.d/00-anna-limits.conf` и `location /` в `anna.conf`; образец — `deploy/nginx.example.conf`. Копии прежних файлов: `/etc/nginx/nginx.conf.bak-*`, `/root/anna.conf.bak-*`.
- **fail2ban `nginx-limit-req`:** адрес, получивший больше 300 отказов 429 за минуту, блокируется в firewall на час, при повторах — дольше.
- **Ядро:** syncookies включены; очередь полуоткрытых соединений — 4096, повторов SYN-ACK — 2 (`/etc/sysctl.d/61-anna-syn.conf`).
- **Проверено:** 800 запросов за секунду с одного адреса — 333 прошли, 467 получили 429; через 10 секунд адрес снова обслуживается.
- **Предел:** от атаки с тысяч адресов или забивания канала один сервер не защитит. Нужна защита на стороне провайдера или российский сервис защиты (DDoS-Guard, Qrator, StormWall). Cloudflare не подходит: трафик с персональными данными пойдёт через зарубежные серверы (152-ФЗ).
- **База:** PostgreSQL слушает только `127.0.0.1`, вход по паролю (scram-sha-256, 24 символа) только с сервера; у `postgres` пароля нет, вход только системным пользователем. Роль сайта `anna` — без прав администратора. Все запросы с параметрами `$1…`: в тексте SQL только константы из кода.
- **Файлы:** код принадлежит `ubuntu`, сайт (`anna`) не может его менять. Секреты (`/etc/anna`) читает только root, копии базы (`/var/backups/anna`) — только `anna`; Nginx (`www-data`) не может прочитать ни то, ни другое. Nginx отдаёт только то, что отдаёт сайт; сайт отдаёт только папку `prototype/`.
