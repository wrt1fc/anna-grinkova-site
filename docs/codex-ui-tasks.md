# Задачи интерфейса для Codex

Бэкенд и модель ведёт другая сессия; здесь описано, что нужно нарисовать поверх уже готовых API. Стиль — текущий: тёмный тёплый фон, бронза и золото, Wix Madefor Display / Roboto / Playfair Display Italic. Без слов «ИИ», «нейросеть», «модель» в интерфейсе. Все ответы API — JSON, ошибки содержат `error` и человекочитаемое `message`, которое можно показывать как есть.

## 1. Согласие на хранение истории чата

Без согласия переписка живёт только в памяти страницы. С согласием сервер хранит последние сообщения до 180 дней.

- Где: в кабинете (блок «Безопасность» или отдельный «Чат») и коротким баннером над полем ввода при первом входе в чат, пока пользователь не ответил.
- Текст (черновик, утвердить с юристом): «Сохранять переписку в чате, чтобы вернуться к ней позже. Храним до 180 дней, удалить можно в любой момент». Две кнопки: «Сохранять» и «Не сохранять».
- API: `PUT /api/chat/consent` с `{ "consent": true | false }`. При `false` сервер сразу удаляет сохранённую историю — предупредите об этом в подтверждении.
- Состояние: `GET /api/chat/history` → `{ consent, messages }`.
- Согласие обязательно по 152-ФЗ: галочка не стоит по умолчанию, отказ не ограничивает чат.

## 2. История переписки

- При открытии чата, если `consent: true`, показать сообщения из `GET /api/chat/history` под приветствием (роль `user` / `assistant`, поле `content`). Для сообщений о близком есть `profileId`.
- Кнопка «Очистить историю» в кабинете: `DELETE /api/chat/history` с подтверждением.
- Восстановленные ответы не подписаны, поэтому в `chatHistory` для продолжения разговора их не добавлять — только показывать.

## 3. Тарифы и близкие люди

Тарифы: «Индивидуальный» (1 человек), «Партнёрский» (вы + партнёр), «Семейный» (вы + ещё двое). Пока оплата не подключена, тариф назначает оператор (`node scripts/set-plan.js <email> <individual|partner|family>`).

- `GET /api/profiles` → `{ plan: { id, label, maxPeople, dailyChatMessages, relations }, self, profiles: [{ id, relation, label, birthDate, birthTime, birthPlace, …, locked }], relationLabels }`.
- `POST /api/profiles` — `{ relation, label, birthDate, birthTime, birthCityId | birthPlace + координаты + birthTimeZone }`, поля как у своего профиля. `relation` — из `plan.relations`. Ошибка `plan_limit` (403) — показать сообщение и ссылку на смену тарифа.
- `PUT /api/profiles/:id`, `DELETE /api/profiles/:id`.
- `label` — до 40 букв, цифр, пробелов (например «Сергей», «Мама»).
- В кабинете: блок «Близкие» со списком карточек и кнопкой «Добавить человека». Форма — та же, что для своих данных рождения, плюс выбор связи (`relationLabels`) и имя. Профили с `locked: true` показывать приглушёнными с подписью «Недоступно на текущем тарифе».
- Счётчик «2 из 3 человек» по `plan.maxPeople`.

## 4. Переключатель «О ком вопрос» в чате

Как «Моя карта / Переключить» у Селены.

- В шапке панели чата: чип с именем текущего профиля («Я», «Сергей»…), по нажатию — список профилей из `GET /api/profiles` (заблокированные недоступны).
- Чат уже читает выбор из функции `window.chatSelectedProfileId()`: она должна вернуть `id` профиля или `null` для себя. Достаточно определить эту функцию.
- В ответе `context.subject` (`{ relation, label }`) — чат уже подписывает ответ «Сергей · Личный расчёт · …».

## 5. Лимиты и состояния чата

- `chat_daily_limit` (429): «Сообщения на сегодня по тарифу закончились» — показать с предложением сменить тариф.
- `chat_busy` (503) и `chat_rate_limited` (429): уже выводятся как ошибка с кнопкой «Повторить».
- `chat_in_progress` (429): у этого пользователя уже идёт ответ. Кнопку отправки и так блокирует чат, но при двух открытых вкладках это сообщение можно показать как подсказку, а не как ошибку.
- Кризисный ответ приходит с `crisis: true` — показать его без кнопки «Скопировать» и без подписи расчёта, можно выделить мягкой рамкой. Номера телефонов сделать ссылками `tel:`.

## 6. Поток ответа

Уже работает: `POST /api/chat` с `Accept: text/event-stream` отдаёт события `delta`, `done`, `error`. Если правите `prototype/chat.js`, не ломайте `readEvents` и замену текста на `done` (так ответ, остановленный проверкой, заменяется безопасным текстом).
