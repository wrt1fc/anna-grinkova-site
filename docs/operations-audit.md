# Проверка ограничений и безопасности — 3 октября 2026

## 1. Лимит трафика

**В коде:** все маршруты `/api/` ограничены до 60 запросов в минуту с одного сетевого адреса и 600 запросов в минуту на процесс. Значения задаются `API_PER_IP_PER_MINUTE` и `API_GLOBAL_PER_MINUTE`. При превышении возвращаются `429` и `Retry-After`. Повторные чтения дневного прогноза используют кэш результата текущей даты. Лимиты проверены тестами.

**Перед публичным запуском:** этот счётчик находится в памяти одного процесса. Несколько процессов будут иметь отдельные лимиты, а статические файлы не ограничены. Подготовлен [`пример Nginx`](../deploy/nginx.example.conf) с внешним лимитом API; его нужно развернуть и проверить под реальной нагрузкой. Адрес берётся из TCP-соединения; приложение не доверяет произвольному `X-Forwarded-For`.

## 2. Защита базы

**В коде:** SQLite хранится вне Git (`data/` в `.gitignore`), используется параметризация SQL, включены внешние ключи и WAL. Пароли хранятся как scrypt-хеши, сессионные токены и коды подтверждения в базе представлены хешами/HMAC. В POSIX-окружении процесс запускается с `umask 077`, поэтому новые файлы доступны только владельцу. Схема проверена тестами миграции и сохранения данных.

**Добавлено:** скрипт `scripts/db.js` делает согласованную резервную копию через SQLite backup API, проверяет целостность и восстанавливает в новый файл; восстановление проверено тестом. **Перед публичным запуском:** настроить приватный каталог для `DATA_PATH`, проверить права уже существующей базы и файлов `-wal`/`-shm`, настроить шифрованное внешнее хранение копий и регулярно проверять восстановление. На Windows права наследуются от каталога. Шифрование SQLite «на диске» сейчас не настроено. Ограничить доступ к серверу и копиям, поскольку дата, время и место рождения относятся к личным данным.

## 3. Ключи в коде

**Проверено:** рабочие значения `UNISENDER_GO_API_KEY` и `AUTH_CODE_SECRET` читаются только из переменных окружения; `.env` и `data/` исключены из Git. В отслеживаемых исходниках найдены имена переменных, примерные заполнители в README и тестовый секрет, но не рабочие ключи. Для `NODE_ENV=production` отсутствие `AUTH_CODE_SECRET` останавливает запуск. Проверка текущих файлов не доказывает отсутствие ранее удалённых секретов в истории Git.

**Перед публичным запуском:** хранить ключи в секретах хостинга, выдавать минимальные права, добавить специализированное сканирование секретов в CI и процедуру ротации. Текущий CI запускает тесты и аудит зависимостей, но не является полноценным сканером секретов. Не записывать токены или полные запросы с личными данными в логи.

## 4. Жёсткий лимит расходов

**В коде:** дневной расчёт и редакционный модуль работают локально и не делают платных запросов к LLM или геокодеру. Необязательная языковая модель обращается только к локальному Ollama; облачного LLM-адреса в коде нет. Сверка с Sotis делает не более одного запроса на дату на процесс и не получает данных пользователя. Платных тарифных API-запросов для генерации прогноза сейчас нет. Для писем действует стойкая квота в SQLite: `MAIL_DAILY_LIMIT=0` по умолчанию, то есть отправка выключена до явного выбора суточной квоты по UTC. После достижения квоты отправка прекращается с `429`; счётчик сохраняется после перезапуска. Неуспешная попытка отправки всё равно расходует квоту, чтобы при неопределённом ответе провайдера не превысить предел.

**Ограничение:** квота в письмах не является денежным потолком: стоимость тарифа Unisender Go, перерасход и расходы на хостинг зависят от договора и провайдера. [Документация Unisender Go](https://godocs.unisender.ru/card-billing-details) описывает возможную плату за превышение пакета. Перед вводом платной LLM необходимо задать максимально допустимые рубли/месяц, стоимость одного запроса, атомарное резервирование бюджета в базе до вызова модели, лимит токенов и внешний жёсткий предел у провайдера. Пока этих настроек нет, платная LLM в приложении не включается.
