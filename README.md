# Сайт Анны Гриньковой

Для продолжения работы с Codex на другом компьютере начните с [CODEX_HANDOFF.md](CODEX_HANDOFF.md).

Сайт использует утверждённый дизайн. Данные хранятся в PostgreSQL. Регистрация требует подтверждения почты шестизначным кодом; смена пароля также подтверждается кодом. Отправка писем подключается через Unisender Go.

## Запуск

Требуется Node.js 24.15 или новее. Астрономические расчёты выполняет локальная библиотека Astronomy Engine.

```powershell
npm ci
npm start
npm test
```

Сайт открывается на `http://127.0.0.1:3000`. База — PostgreSQL по `DATABASE_URL` (`postgres://…`). Без неё для разработки используется PGlite — тот же PostgreSQL внутри Node — в папке `data/pglite` (исключена из Git); тесты работают на PGlite в памяти. Настройки сервера: `PORT`, `HOST`, `DATABASE_URL`.

Дневной прогноз доступен на `/api/forecast/day` и на странице «Карта дня». Гость получает общий прогноз. После входа и сохранения даты, времени и **выбранного из каталога** города рождения тот же маршрут возвращает персональный расчёт: натальные положения планет, дневные транзиты, аспекты, точные дневные события и отдельную цифровую карту таро. Если города нет в каталоге, координаты и пояс можно указать вручную. Старый профиль со свободным названием города нужно уточнить в кабинете. Прогноз на неделю пока не подключён.

При первом запросе за день сервер автоматически получает положения Солнца и Луны с Sotis и сверяет их с локальным расчётом. Используется внутренний интерфейс веб-приложения Sotis: он не документирован как API, поэтому при недоступности или изменении формата прогноз сохраняется на локальном расчёте. Запрос к Sotis кэшируется на день и содержит только дату и фиксированный город Москву, без данных аккаунта. Для отключения сверки задайте `SOTIS_VERIFY=0`.

На этом ПК установлен локальный Ollama с `qwen3.5:4b`. Чтобы включить его для **общего** дневного прогноза, запустите `scripts/start-local-ollama.ps1`, затем задайте `FORECAST_LOCAL_MODEL=qwen3.5:4b` перед `npm start`. Модель добавляет только короткое пояснение: рассчитанные факты, совет и вопрос остаются неизменными. При ошибке используется редакционный текст. Установка, проверка и ограничения описаны в [docs/local-model.md](docs/local-model.md).

На странице «Помощник Анны» отвечает явно обозначенный ИИ-помощник. Чат доступен только после входа. Он получает сведения о проекте и краткий расчёт карты дня; для вошедшего пользователя с профилем учитывается персональный контекст дня. Чат использует `CHAT_LOCAL_MODEL`, а если переменная не задана — `FORECAST_LOCAL_MODEL`. Диалог не хранится в базе. Одновременно модель обрабатывает не больше `CHAT_MAX_CONCURRENT` вопросов (по умолчанию 2), остальные сразу получают ответ «помощник занят». Источники знаний, правила обновления и проверка ответов описаны в [docs/ai-context.md](docs/ai-context.md).

На главной доступен выбор одной из пяти закрытых карт. Выбранная позиция получает расчётную карту и ведёт к соответствующему прогнозу на день. Вертикальный и горизонтальный портреты предоставлены заказчиком; версии с тёплым тёмным фоном используются на сайте и в SVG.

## Подключение писем

Для отправки кодов нужны аккаунт [Unisender Go](https://godocs.unisender.ru/web-api), проверенный адрес отправителя и три серверные переменные:

```powershell
$env:UNISENDER_GO_API_KEY = '<ключ из кабинета Unisender Go>'
$env:MAIL_FROM = 'no-reply@ваш-домен.ru'
$env:AUTH_CODE_SECRET = '<случайный секрет длиной от 32 символов>'
$env:MAIL_DAILY_LIMIT = '100'
npm start
```

Ключ и секрет нельзя коммитить. Без почтовых настроек новая регистрация отвечает `503` и не создаёт аккаунт, так как подтвердить почту невозможно. В рабочем окружении `AUTH_CODE_SECRET` обязателен, а `NODE_ENV=production` включает флаг `Secure` для сессионной cookie. Публичный запуск требует HTTPS.

Коды действуют 10 минут, допускают пять попыток и не отправляются повторно чаще одного раза в минуту. В SQLite хранится HMAC кода, сам код не сохраняется. После смены пароля все старые сессии удаляются. Старые аккаунты из предыдущей версии базы сохраняются без отметки о подтверждении почты; пользователь может подтвердить адрес в кабинете.

## Текущий состав

- `prototype/` — страницы сайта и личного кабинета.
- `design/svg/variant-1-*.svg` — экраны для импорта в Figma, включая выбор карты; `design/preview/` и `design/variant-1-svg.zip` — материалы просмотра.
- `PRODUCT.md` и `DESIGN.md` — продуктовые и визуальные решения.
- `server/db.js`, `server/schema.js`, `server/store*.js` — подключение к PostgreSQL, миграции и хранилище (см. [docs/database.md](docs/database.md)).
- `docs/project-analysis.md` — источники, гипотезы о ЦА, путь пользователя и ход разработки; отдельная страница анализа есть в Figma.
- `server/http.js` — API регистрации, входа, подтверждения почты, смены пароля и профиля.
- `server/mail.js` — адаптер Unisender Go.
- `test/` — проверки кодов, аккаунтов, профиля и миграции.
- `docs/payments.md` — задача подключения оплаты на более поздний этап.
- `docs/forecast.md` — расчётная модель и следующий этап персонализации.
- `docs/ai-context.md` — роль ИИ-помощника, источники знаний и план наполнения.
- `docs/operations-audit.md` — проверка трафика, базы, ключей и расходов.
- `docs/server-transfer.md` — перенос, резервное копирование, восстановление, мониторинг и прокси.

Тарифы (`config/plans.json`): «Индивидуальный» — 1 человек, «Партнёрский» — 2, «Семейный» — 3; у каждого дневной лимит сообщений в чате. До подключения оплаты тариф назначает оператор: `node scripts/set-plan.js <email> <individual|partner|family>`. Близкие люди хранятся в кабинете (`/api/profiles`), и чат может отвечать о любом из них. История чата сохраняется только с согласия пользователя (`/api/chat/consent`) и не дольше 180 дней. Ответ чата приходит потоком (SSE); сообщения о суициде и самоповреждении не уходят в модель — пользователь сразу получает номера помощи из `config/crisis.json`, их нужно сверить перед запуском. Статистика трафика и чата: `node scripts/stats.js [дней]`; IP-адреса не хранятся.

## Структура папок

```
prototype/            сайт: HTML, CSS, JS
  assets/             изображения, используемые на сайте (портреты в WebP + JPEG)
  assets/fonts/       локальные шрифты и fonts.css
design/
  svg/                шесть экранов для импорта в Figma и эмблема Института
  preview/            PNG для быстрого просмотра
  source/             исходные портреты от заказчика без обработки
  variant-1-svg.zip   архив SVG
PRODUCT.md, DESIGN.md продуктовые и визуальные решения
local/                (не в git) архив второго варианта, записи и старые материалы
figma-export/         (не в git) скрипты экспорта сайта в SVG
```

Портреты предоставлены заказчиком. Исходники лежат в `design/source/`, а версии с тёплым тёмным фоном — в `prototype/assets/`. Эмблема и декоративные изображения подготовлены по фирменным материалам Института астрологии и психологии. Шрифты Wix Madefor Display, Roboto и Playfair Display распространяются по лицензии SIL Open Font License.

Сервер задаёт Content-Security-Policy заголовком (`server/http.js`): скрипты, стили, шрифты и изображения загружаются только с того же домена, шрифты лежат на сайте.

После правок CSS или JS увеличьте номер `?v=` в подключениях в `index.html`, чтобы браузеры не взяли старую версию из кэша.

Лимиты API и писем настраиваются переменными `API_PER_IP_PER_MINUTE` (по умолчанию 60), `API_GLOBAL_PER_MINUTE` (600), `MAIL_DAILY_LIMIT` (по умолчанию 0: письма отключены до явного выбора квоты). Отправка писем прекращается после достижения дневной квоты по UTC. За Nginx задайте `TRUST_PROXY=1`: тогда лимит считается по адресу посетителя из `X-Real-IP`, а не по общему адресу прокси. Вход блокируется на 15 минут после 10 неудачных попыток для одного email.

Резервные копии: основная защита — копии с восстановлением на любую минуту у провайдера PostgreSQL; дополнительная — `node scripts/db.js backup <файл.dump>` (pg_dump). Проверка сервиса: `GET /api/health`.
