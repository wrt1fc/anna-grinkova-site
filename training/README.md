# Дообучение помощника под манеру Анны

Цель — чтобы ИИ-помощник объяснял так, как объясняет Анна: от астрологического показателя к понятной жизненной ситуации, затем к выводу и одному действию. Дообучение передаёт **манеру**, но не знания. Факты о проекте и расчёт дня по-прежнему передаются в каждом запросе (`config/chat-context.json`, `server/local-chat.js`). Помощник остаётся ИИ-помощником: не говорит от имени Анны и не пересказывает её личную жизнь.

## Где что лежит

| Что | Где | В Git |
| --- | --- | --- |
| Скрипты конвейера | `training/` | да |
| Записи эфиров и сырые расшифровки | `D:\AnnaAI\data\<запись>\` | **нет**: в них данные участников |
| Карточки вопрос — ответ | `D:\AnnaAI\data\dataset\cards.jsonl` | нет, до согласования с Анной |
| Собранный датасет | `D:\AnnaAI\data\dataset\build\` | нет |
| Обученные адаптеры | `D:\AnnaAI\adapters\` | нет |

Расшифровка делается локально: `D:\AnnaAI\scripts\transcribe.py` (faster-whisper `large-v3-turbo` на GPU). Запись в облако не уходит.

## Формат карточки

Одна строка `cards.jsonl` — одна карточка:

```json
{"id": "rec01-moon-elements", "status": "draft", "split": "train", "topic": "Луна и любовь",
 "question": "Как Луна влияет на то, как человек чувствует любовь?",
 "answer": "Смотрите, Луна показывает, через что человек чувствует заботу...",
 "source": {"file": "record.ogg", "from": "00:02:24", "to": "00:10:10"},
 "note": "манера: показатель → пример → вывод"}
```

- `status`: `draft` — черновик; `approved` — Анна согласовала; `rejected` — не использовать.
- `split`: `train` — для обучения; `eval` — эталонные ответы Анны для проверки. Они **никогда** не попадают в обучение.
- `answer`: от 40 до 1200 символов. Это ответ помощника в чате, поэтому длинное объяснение из эфира сокращается до 2–5 предложений.

Чего в карточках быть не должно: имён, историй и данных рождения участников эфира, личной жизни Анны, мата, цен, ссылок, обещаний исхода, речи от первого лица Анны. Валидатор ловит часть этого автоматически (те же правила, что и проверка ответов чата), остальное остаётся за редактором.

## Порядок работы

```bash
# 1. Проверить карточки (имена участников можно перечислить в файле, по одному в строке)
node training/validate-cards.js D:/AnnaAI/data/dataset/cards.jsonl --names D:/AnnaAI/data/dataset/names.txt

# 2. Собрать датасет из одобренных карточек в формате боевого запроса чата
node training/build-dataset.js D:/AnnaAI/data/dataset/cards.jsonl D:/AnnaAI/data/dataset/build

# 3. Обучить LoRA-адаптер (сервер с GPU; на 8 ГБ — только пробный прогон маленькой модели)
python training/train_lora.py --base <модель> --data D:/AnnaAI/data/dataset/build --out D:/AnnaAI/adapters/anna-v1
```

`build-dataset.js` берёт системные инструкции и факты из `config/chat-context.json` и добавляет к каждому примеру реальный расчёт одного из дней. Модель учится отвечать в стиле Анны в том же формате, в котором её потом вызывает сайт. Флаг `--include-drafts` нужен только для пробного прогона: черновики не согласованы.

## Сколько нужно данных

- Для проверки: 20–30 эталонных ответов Анны (`split: eval`).
- Для заметного переноса манеры: 300–1000 одобренных пар. Одного эфира на 68 минут хватает примерно на 30–40 пар. Нужны ещё эфиры или посты, разрешённые к использованию.

## После обучения

1. Прогнать эталонные вопросы через базовую и дообученную модели, а ответы показать Анне вслепую.
2. Если дообученная модель лучше, на сервере запустить базовую модель в vLLM с адаптером (`--enable-lora`). Другой вариант — слить адаптер с моделью и конвертировать в GGUF для Ollama.
3. Указать модель в `CHAT_LOCAL_MODEL`. Проверка ответов (`server/chat-safety.js`) работает независимо от модели.
